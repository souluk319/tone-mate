## 1. 한 줄 아이디어

사용자가 들은 음을 얼마나 정확히 구별하고 목소리로 재현하는지 측정한 뒤, 개인 음역에 맞춘 상대음감 및 발성 훈련을 제공하는 모바일 앱을 만든다.

단순한 튜너나 일회성 테스트가 아니라, 사용자가 자신의 약점을 이해하고 매일 개선 과정을 확인할 수 있는 실제 음악 훈련 제품을 지향한다.

## 2. 문제의식

사람이 음정을 정확하게 내지 못하는 이유는 하나가 아닐 수 있다.

- 음의 높낮이를 구별하는 능력이 부족할 수 있다.
- 음은 구별하지만 원하는 높이로 발성하는 제어가 부족할 수 있다.
- 처음에는 맞지만 음을 안정적으로 유지하지 못할 수 있다.
- 자신의 편안한 음역보다 너무 높거나 낮은 음을 요구받았을 수 있다.
- 주변 소음, 마이크, 반주 환경이 측정을 방해할 수 있다.

따라서 하나의 `음치 점수`만 보여주기보다 음정 지각과 음정 발성을 분리하여 측정하고, 결과에 맞는 훈련을 추천하는 것이 제품의 핵심 차별점이 될 수 있다.

## 3. 제품 방향

### 제품이 지향하는 것

- 실제로 빌드·배포하고 지속해서 사용할 수 있는 모바일 제품
- 짧게 반복할 수 있는 일일 음정 훈련
- 초보자도 이해할 수 있는 시각적·청각적 피드백
- 테스트 결과가 곧 개인 훈련 계획으로 이어지는 경험
- 음정 정확도와 변화 추이를 구체적인 수치와 그래프로 확인하는 경험

### 제품이 지향하지 않는 것

- ChainShield 검증만을 위한 일회성 테스트 앱
- 단일 튜너 화면만 제공하는 도구
- 사용자를 의학적·임상적으로 `음치`라고 진단하는 서비스
- 음정 정확도만으로 목소리의 좋고 나쁨을 평가하는 서비스
- 검증되지 않은 기준으로 절대적인 음악 능력 등급을 부여하는 서비스

## 4. 핵심 사용자 경험

### 4.1 시작 및 음역 확인

1. 마이크 사용과 측정 환경을 안내한다.
2. 사용자가 편안하게 낼 수 있는 낮은 음과 높은 음을 확인한다.
3. 이후 테스트와 훈련에서 사용할 기준 옥타브와 안전한 음역을 설정한다.

C 메이저 스케일을 사용하더라도 모든 사람에게 고정된 C4부터 부르게 하지 않고, 사용자의 음역에 맞는 C3·C4·C5 등의 시작점을 선택하는 방향을 고려한다.

### 4.2 음정 지각 테스트

음성 입력 없이도 수행할 수 있는 청음 테스트다.

- 두 음을 차례로 들려주고 두 번째 음이 더 높은지, 낮은지, 같은지 선택한다.
- 쉬운 간격부터 시작해 더 작은 음정 차이로 난이도를 조절한다.
- 단일 음 비교, 음정 방향, 간단한 멜로디 윤곽 순으로 확장할 수 있다.

이 테스트는 사용자가 음정을 듣고 구분하는 능력을 확인한다.

### 4.3 기준음 따라 부르기

1. 피아노나 사인파 등의 기준음을 약 1초간 들려준다.
2. 짧은 준비 시간을 둔다.
3. 사용자가 같은 높이의 음을 일정 시간 발성한다.
4. 앱이 목표 음정과 실제 발성의 차이를 분석한다.

초기 측정 후보는 다음과 같다.

- 목표 음까지의 평균 오차
- 음을 맞추는 데 걸린 시간
- 유지 구간의 음정 안정도
- 음을 유지한 시간
- 한 옥타브 위나 아래로 잘못 부르는 오류

테스트 중에는 실시간 튜너 표시를 숨겨 순수 재현 능력을 측정하고, 훈련 중에는 실시간 피드백을 보여주는 방식을 고려한다.

### 4.4 C 메이저 발성 훈련

초기 훈련은 이해하기 쉬운 C 메이저 스케일을 중심으로 구성한다.

- 도–레–미–파–솔–파–미–레–도
- 도–미–솔–미–도
- 도–레–미–파–솔–라–시–도
- 한 음을 정확하게 시작하고 유지하기
- 두 음 또는 세 음 패턴을 듣고 따라 부르기
- 기준음 이후 특정 계이름을 상대적으로 찾아 부르기

훈련은 사용자의 음역과 이전 성공률을 반영하여 음의 높이, 간격, 속도와 유지 시간을 조절하는 방향으로 발전시킨다.

### 4.5 결과와 훈련 추천

결과는 하나의 낙인형 점수보다 능력을 나누어 보여준다.

- 음정 지각
- 음정 재현
- 발성 진입 정확도
- 음정 안정도
- 평균 음정 오차
- 편안한 발성 음역
- 이전 측정 대비 변화

결과에 따라 `음 시작점 맞추기`, `음 유지하기`, `상행·하행 구별`, `장2도 패턴` 같은 다음 훈련을 추천한다.

## 5. 초기 MVP 가설

첫 번째 제품 버전은 다음 네 개의 흐름에 집중한다.

1. 마이크 및 음역 캘리브레이션
2. 짧은 음정 지각 테스트
3. 기준음 따라 부르기 테스트
4. 개인 음역에 맞춘 C 메이저 일일 훈련과 변화 기록

초기 화면 후보는 다음과 같다.

- 온보딩 및 측정 환경 안내
- 음역 확인
- 오늘의 테스트
- C 메이저 훈련
- 결과 상세
- 주간·월간 변화 기록

## 6. 측정 방식에 대한 초기 기술 가설

스마트폰 마이크로 입력된 단선율 음성에서 기본 주파수를 실시간 추정하고, 목표 주파수와의 차이를 센트 단위로 계산한다.

```text
센트 오차 = 1200 × log2(측정 주파수 / 목표 주파수)
```

초기 구현에서는 일반 튜너와 유사한 방식으로 시작할 수 있다. 다만 실제 제품 품질을 위해 다음 처리가 필요할 가능성이 있다.

- 음성 시작과 종료 감지
- 배경 소음 제거 또는 무음 임계값
- 안정적인 발성 구간 선택
- 비브라토와 자연스러운 주파수 흔들림 처리
- 옥타브 오류 탐지
- 기기별 마이크 차이 대응
- 실시간 처리 지연 최소화

피치 검출 후보는 YIN, pYIN, 경량 CREPE로 좁혔다. 최종 알고리즘과 정확도 기준은 동일 녹음·소음·실제 기기 조건의 비교 실험 후 결정한다.

## 7. 모바일 제품 기술 구성 가설

아직 확정하지 않지만, 실제 제품과 Native·Mobile 생태계 검증을 함께 만족시키는 구성으로 다음을 검토할 수 있다.

- Flutter/Dart: 공통 모바일 UI와 앱 로직, Pub 생태계 사용
- CocoaPods: iOS 오디오·마이크 및 필요한 네이티브 플러그인 의존성
- SwiftPM: iOS의 AVAudioEngine 기반 오디오 처리 또는 보안·플랫폼 모듈
- Conan: iOS·Android에서 공유할 수 있는 C++ DSP 또는 피치 검출 코어

네 기술을 사용하기 위해 제품 구조를 억지로 복잡하게 만들지는 않는다. 각 기술이 실제 기능과 유지보수 측면에서 타당한지는 기술 검증 후 결정한다.

이 앱은 ChainShield 저장소 안의 fixture가 아니라 별도 제품·별도 저장소로 개발하는 것을 원칙으로 한다. 완성된 고정 commit을 ChainShield의 Native·Mobile 실사용 E2E 대상으로 활용하는 것은 부가적인 효과다.

## 12. 딥리서치 반영 요약

### 유지하는 원래 방향

- 테스트용 fixture가 아니라 실제 사용자가 반복해서 쓰는 독립 모바일 제품을 만든다.
- 음정 지각과 목소리 재현 능력을 분리한다.
- 사용자의 편안한 음역에 맞춘 C 메이저·도수 훈련을 초기 중심으로 둔다.
- 스마트폰 마이크의 실시간 피치 검출을 핵심 기술로 사용한다.
- 결과가 곧 다음 일일 훈련으로 연결되게 한다.

### 조사 후 보정한 방향

1. **`음치 판정`을 제품 결과로 쓰지 않는다.** 유입 문구로 테스트라는 표현은 사용할 수 있지만, 결과는 듣기·목표음 진입·음 유지·음정 이동·타이밍을 나눈 `음정 감각·보컬 제어 프로필`로 제시한다.
2. **C 메이저를 고정 C4로 부르게 하지 않는다.** 화면에는 도–레–미와 음계 도수를 유지하고 실제 음은 사용자의 편안한 음역으로 전조한다.
3. **실시간 피드백만으로 성공을 판정하지 않는다.** 훈련 중 피드백을 점차 줄이고, 화면을 끈 직후와 다음 날 다시 측정해 실제 유지와 전이를 확인한다.
4. **평균 센트 오차 하나를 총점으로 쓰지 않는다.** 안정 구간 정확도, 목표음 도달 시간, 간격 오차, 윤곽, 타이밍, 옥타브 오류, 신호 신뢰도를 분리한다.
5. **사람 목소리 기준음을 포함한다.** 연구상 모방할 음색이 비슷할 때 초보자의 피치 매칭에 도움이 될 가능성이 있어 피아노·사인파와 함께 비교한다.
6. **핵심 분석은 기기 내 처리를 기본값으로 한다.** 원음은 기본 저장·전송하지 않고, 사용자가 전후 비교를 선택한 경우에만 보관한다.
7. **발성 안전을 기능 요구사항으로 둔다.** 통증·쉰 목소리·피로가 있으면 중단시키고, 무리한 최고음·매일 음역 확장을 보상하지 않는다. 의료 진단·치료 표현은 사용하지 않는다.
8. **첫 버전에서 상용곡을 제외한다.** 자체 기준음·MIDI 패턴·자체 멜로디·권리 확인된 퍼블릭 도메인 재료로 시작한다. 곡 카탈로그는 권리와 사업성을 별도로 검증한 뒤 확장한다.
9. **AI는 핵심 판정자가 아니라 설명 보조로 제한한다.** 신호 분석이 관찰한 범위 안에서 세션 요약, 회고 질문, 다음 연습 이유를 설명하는 데 사용한다.

### 새로 추가한 핵심 아이디어

- **피드백 의존도:** 피치선을 켰을 때와 껐을 때의 성과 차이를 보여준다.
- **셀프 보이스 기준음:** 사용자의 안정된 한 음을 기기 안에서 피치 이동해 자기 음색의 목표음으로 들려준다.
- **도착 방식 분석:** 목표음에 즉시 도착하는지, 아래서 밀어 올리는지, 위에서 내려오는지 구분한다.
- **다음 날 유지 검사:** 당일 훈련 성과가 아닌 실제 기억된 능력을 추적한다.
- **측정 신뢰도 UI:** 소음·입력 부족·불안정 신호에서는 거짓 정밀도 대신 재측정을 안내한다.
- **주간 멜로디 전이:** 매일 연습하지 않은 짧은 멜로디로 학습이 일반화됐는지 확인한다.
- **코치 공유 1분 리포트:** 자동 분석이 애매하거나 정체된 경우 보컬 트레이너가 빠르게 볼 수 있는 요약을 만든다.
- **안전 에스컬레이션:** 학습 정체는 보컬 코치로, 통증·지속적 쉰 목소리는 의료·음성 전문가 안내로 경로를 분리한다.

## 13. 보정된 MVP

첫 제품은 다음 흐름만 완성도 있게 만든다.

1. 마이크·소음·이어폰 환경 확인
2. 편안한 음역 캘리브레이션
3. 높음/낮음/같음 음정 지각 테스트
4. 사람 목소리·피아노 기준음 따라 부르기
5. 개인 음역으로 전조된 C 메이저 두·세 음 패턴
6. 실시간 피드백 훈련 → 피드백 감쇠 → 무피드백 재검사
7. 다축 결과와 실패 유형별 다음 5분 루틴
8. 로컬 기록과 주간 변화
9. 안전 중단 안내와 원음 비저장 기본값

상용곡, AI 발성 진단, 전문 성악 테크닉, 코치 마켓플레이스, 소셜 랭킹은 MVP에서 제외한다.
